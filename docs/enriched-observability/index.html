Enriched Observability

Raw → processed → analytic: a three-stage AI enrichment pipeline that turns 18 alerts into one causal chain.

1The problem

Engineers triage raw telemetry: 18 alerts for one incident, each layer speaking its own dialect. Classical detectors flag; nobody translates. The CTO gets the same alert storm as the on-call engineer.

2The current gap

Pipelines stop at 'processed' (anomaly scores, dashboards). The analytic stage — failure probability, root-cause confidence, business impact, recommended action, role-tailored narrative — is manual, slow, and inconsistent.

3How the solution addresses it

A per-layer three-stage pipeline: raw telemetry → processed (robust median/MAD anomaly scores, trend-slope breach forecasting, k-means symptom clustering, lagged cross-correlation) → analytic (failure probability, root-cause confidence, impact score, rule-based recommendations) → a cross-layer chain reconstructor (onset order + correlation strength) → five role views (CTO, SRE director, DevOps lead, eng manager, engineer), each scored on a relevance rubric.

6Insights

  • Onset order beats correlation for linking. Step-like cascades make lagged-correlation direction ambiguous; temporal order plus |r| is robust.
  • Neither detector dominates. Robust wins precision and gradual onsets; naive thresholds win recall when they happen to be right — report both.
  • Relevance is measurable. Scoring each role's view against a rubric turns 'executive summary' from art into engineering.
