Trust, Recovery & Evidence

Behavioral Regression

Your vendor shipped a new model version. Did your agent silently get worse? Find out before production does.

1The problem

Model vendors ship new versions; agent task success, tool-call formats, latency, and cost profiles shift silently. Teams discover regressions from production incidents, not tests — because no behavioral regression suite exists for their agents.

2The current gap

Ideological drift is measured (system 13); FUNCTIONAL drift is not. Nobody runs a frozen task battery with paired statistical tests across model versions, staged canaries, and pin/adopt/rollback policy.

3How the solution addresses it

A frozen 120-task regression battery (tool use, multi-step, instruction following, edge cases incl. must-refuse) run against 5 versioned model stand-ins; paired statistical tests (McNemar exact + t-tests; regression only if significant AND material); business-weighted severity ranking; staged canary (1% → 10%) with stop rules; and a pin/auto-adopt/rollback policy engine with rationales.

4Architecture

Blueprint of the Behavioral Regression architecture. See the repo for the full implementation.

6Insights

  • Rank by business severity, not by p-value. A silent tool-format break outranks a verbosity change 10-to-1.
  • Canary and battery are complementary. Staged rollout catches big breaks fast; the full suite catches subtle trade-offs.
  • 60 tasks is the floor. Below it the battery is blind — size your suite deliberately.
