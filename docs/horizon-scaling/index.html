Horizon Scaling

How fast does reliability die with task length — and which architecture flattens the curve?

1The problem

Agents succeed on short tasks and collapse on long ones: error compounds with horizon length. Teams deploy 80-step agents with no measurement of the decay curve and no evidence for which mitigation — checkpoints, hierarchy, voting, recovery — actually helps at their horizon.

2The current gap

The decay is discussed qualitatively ('agents fail on long tasks') but never fitted. Without the curve you cannot choose mitigations, price cost-per-success, or know the horizon at which your architecture stops being viable.

3How the solution addresses it

A seeded long-horizon task simulator (compounding corruption: corrupted state triples fatal probability) with a baseline linear executor and four mitigations sharing one verify-and-rollback core — checkpoints, hierarchical decomposition, healflow-style recovery, per-step majority voting — plus a cost model computing cost-per-successful-task at each horizon.

4Architecture

Blueprint of the Horizon Scaling architecture. See the repo for the full implementation.

6Insights

  • The decay is exponential, not anecdotal. Fit q=0.959 vs theoretical 0.960 — the curve is predictable, so plan against it.
  • Mitigations are pure overhead on short tasks. Below N=10 the baseline wins on cost; hierarchy pays off only at length.
  • Match the mitigation to the error mix. Fatal errors want checkpoints; corruption wants hierarchy; voting is never cheapest.
